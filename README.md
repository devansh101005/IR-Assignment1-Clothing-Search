# Clothing Search Engine - CSD358 Information Retrieval, Assignment 1

A small search engine over 100 clothing product descriptions, built from
scratch in Python: an inverted index, `lnc.ltc` vector space ranking, a
positional index with phrase and proximity search, and two user interfaces.

**Devansh Pandey** (2310110461) · **Abhinav Bachchas** (2310110383)

> No third-party libraries. Standard library Python 3 only - no NLTK, no
> scikit-learn, no numpy. The stemmer, the cosine ranking, the positional
> intersection and the edit distance are all implemented in this repository.

---

## Quick start

```bash
python build_index.py      # build both indexes, write the dumps to output/
python run_tests.py        # run the full Part E test plan
python search_gui.py       # the window interface  (recommended)
python search_cli.py       # the terminal interface
```

Every module also runs on its own and prints a self-check of just that stage:

```bash
python preprocess.py       # see the tokenizer and stemmer on one sentence
python indexer.py          # postings for one term
python vsm.py              # a ranked query plus its score arithmetic
python positional.py       # a phrase query and a proximity query
python novelty.py          # smallest-window, spelling correction, PB-VSM
```

## What it does

| Part | Feature | Where |
|---|---|---|
| A | Tokenisation, stop-word policy, stemming | `preprocess.py` |
| A | Inverted index - `term → df → [(docID, tf)]` | `indexer.py` |
| B | `lnc.ltc` cosine ranking, top 10, ties by docID | `vsm.py` |
| C | Positional index - `term → df → [(docID, tf, [p…])]` | `indexer.py` |
| C | Exact phrase search (positional intersection) | `positional.py` |

| E | Full test plan, no hard-coded docIDs | `run_tests.py` |
| * | **PB-VSM proximity re-ranking + spelling correction** | `novelty.py` |

## The interesting bit

This corpus has a trap in it. Every one of the 100 products ends with the
**same boilerplate sentence**, so **27 of the 127 dictionary terms appear in
all 100 documents** - including words a shopper would really type:

```
wear  regular  festive  casual  comfort  size  colour  fit(*)  ...
```

For all of them `idf = log10(100/100) = 0`, which means **the cosine score
literally cannot see them.** Query `regular fit` and plain `lnc.ltc` ranks on
`fit` alone, so *"Women's **Casual Fit** Dress"* comes out at rank 1.

The positional index fixes it. `novelty.py` re-scores the ranked list by how
tightly the query terms sit together:

```
final_score = cosine × (1 + α × coverage × tightness)
```

…and all ten *Regular Fit* products jump to the top, because their titles have
the two terms adjacent (`span = 2`). Same query, same index, 5 of 10 documents
swapped.

<sub>(*) `fit` has df = 45, not 100 - but it is dominated by the boilerplate phrase "comfortable fit".</sub>

Full write-up with the worked arithmetic, the test results and the honest
limitations: **[REPORT.md](REPORT.md)**.

## Query syntax

**Free-text mode** - just type it:

```
black cotton t-shirt
warm fleece hoodie for winter
```

**Phrase / proximity mode**:

```
cotton shirt               exact phrase
"stretch denim"            quotes optional
cotton WITHIN/3 shirt      ordered proximity, within 3 token positions
```

**CLI commands**: `stats`, `term <word>`, `explain <docID>`, `boost on|off`,
`alpha <n>`, `help`, `quit`.
